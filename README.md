# Listener v0.8

完全オフラインの音声入力・議事録ツール。文字起こし（whisper.cpp）も要約（llama.cpp）も
すべてPC内で完結し、音声・テキストが外部へ送信されることはありません。
議事録は Notion 風のページ／ブロック構造で保存されます。

## 中核 — 出典リンク

要約の各要点には、**根拠となった発言へのリンク**が自動で付きます。
`[1]` をクリックすると文字起こしの該当箇所へジャンプし、その発言がハイライトされます。

対応する発言が見つからない要点には、あえてリンクを張らず「根拠なし」と表示します。
LLM が創作した内容をそこで見分けられるようにするためです。

技術的には、LLM にセグメントIDを出力させていません（3Bクラスのモデルは
存在しないIDを捏造するため）。生成後の要約と文字起こしを、
文字バイグラムのIDF重み付き一致で機械的に突き合わせています。

## 会議タイプ別の要約

会議の性質に応じて要約の構成が変わります。採用面接に「決定事項」を求めても空振りしますし、
1on1 に「決定事項」という言葉を当てると硬すぎます（実態は「合意」）。

| タイプ | 見出し構成 |
|---|---|
| 定例・進捗報告 | 概要 / 報告事項 / 決定事項 / アクション / 課題・持ち越し |
| 部会・報告会 | 概要 / 報告事項 / 決定事項 / 課題・リスク / アクション / 持ち越し |
| 1on1・面談 | 概要 / 本人の状況 / 相談・課題 / 合意した方針・支援 / 次回まで |
| 商談・協業検討 | 概要 / 先方の状況 / 提示内容 / 反応・懸念 / 決定事項 / ネクストアクション |
| 採用面接・顔合わせ | 概要 / 経歴・スキル / 志向・希望条件 / 懸念点 / 申し送り |
| ブレスト・意見交換 | 概要 / 出たアイデア / 有望な方向性 / 論点 / 次に検討すること |
| 一般・その他 | 概要 / 決定事項 / アクション / 論点 / 持ち越し |

タイプはタイトルから自動判定されます。ページ上部のセレクタで手動変更でき、
手動指定は以後の自動判定より優先されます（変更後は「要約を再生成」で反映）。

## アクションアイテムの構造化

要約から担当者と期限を取り出し、**日本語の相対表現を実日付に変換**します。

- 「来週金曜」「今月末」「3日後」「8/30」「2週間後」などを会議日を基準に解釈
- 解釈できない表現は推測せず、元の表記のまま残します
- 「山田さん」「佐藤部長」などの敬称・役職は姓に名寄せ

サイドバーの「アクション」で全議事録を横断し、**期限超過 / 今日 / 今週中 / 先の予定 / 期限なし**
にグループ分けして表示します。担当者での絞り込みも可能です。
担当・期限のチップはクリックで手修正できます。

## 機能

### 議事録
- 録音 → 約75秒ごとにリアルタイム文字起こし（最初の1回は20秒で早く結果を出す）
- 終了時にローカルLLMが要約を生成（概要／決定事項／アクションアイテム／論点／持ち越し）
- 会議タイプ別の要約構成（自動判定・手動変更可）
- 担当者・期限を自動抽出し、実日付へ正規化
- 出典リンク付きのブロック表示。テキストはクリックで直接編集可能
- チェックボックス、行の追加（Enter）・削除（空行でBackspace）
- 一覧から検索、アクション横断ビュー（期限順・担当者別）、全文検索
- Markdown書き出し
- クラッシュ耐性: 文字起こしは区間ごとに自動保存され、強制終了しても次回起動時に復旧

### 音声入力
- どのアプリでも `Ctrl+Shift+Space` → 話す → カーソル位置へ自動貼り付け
- フィラー除去、ユーザー辞書、マイク選択、統計

### ホットキー
- `Ctrl+Shift+Space` … 音声入力（変更可）
- `Alt+M` … 議事録の開始／終了（変更可）

## セットアップ

社内プロキシ環境では最初に一度: `setx NODE_USE_SYSTEM_CA 1` → PowerShellを開き直す

```powershell
cd <Listenerを置いたフォルダ>
npm install
npm start
```

### 文字起こしエンジン（必須）
```powershell
powershell -ExecutionPolicy Bypass -File .\setup-local-engine.ps1 -Model kotoba
```
日本語特化の kotoba-whisper（高速）と VADモデルを取得します。
表示されたパスを [設定] → [文字起こしエンジン] に貼り付け → 起動テスト。

### 要約エンジン（議事録の自動要約に必要）
```powershell
powershell -ExecutionPolicy Bypass -File .\setup-summarizer.ps1
```
llama.cpp と Qwen2.5-3B（約1.9GB）を取得します。`-Model 7b` で高品質版。

※ セットアップ時のみネット接続が必要です。以後は完全オフラインで動作します。

## データ保存先

`%APPDATA%\koetype\`（フォルダ名は互換のため据え置き）
```
settings.json          設定
history.json           音声入力の履歴
data/
  index.json           議事録の一覧（起動時にこれだけ読む）
  pages/<id>.json      ページ本体（プロパティ + ブロック）
  transcripts/<id>.json 文字起こし（重いので分離）
  draft.json           記録中の議事録（正常終了時に消える）
```
設定画面の「データ保存先を開く」からエクスプローラーで開けます。
バックアップはこのフォルダをコピーするだけです。

## 起動方法

### インストーラー（配布するならこれ）

リリースページに `Listener-<版>-setup.exe` が添付されています。配布先はこれを
落として実行するだけです。手元でビルドする必要はありません。

https://github.com/Kishi-Satoshi/Listener/releases/latest

**ブラウザでのダウンロードが途中で止まる場合**（社内回線は大容量ダウンロードを
切ることがあります）は、同じリリースに添付してある `get-installer.ps1` を使ってください。
切断されても続きから再開し、最後にサイズと SHA256 を照合します。

```powershell
powershell -ExecutionPolicy Bypass -File .\get-installer.ps1
```

この大きなファイルを落とすのは初回だけです。以降の更新は数百KBの差分のみを取得します。

手元でビルドしたい場合は `npm run dist:installer` で `dist\Listener-<版>-setup.exe`
ができます。ただし electron-builder が取得する `winCodeSign` に macOS 用の
シンボリックリンクが含まれるため、Windows では特権が無いと展開に失敗します
（「クライアントは要求された特権を保有していません」）。その場合は
開発者モードを有効にするか、管理者権限で一度だけ実行してください。
リリース用のインストーラーは GitHub Actions の Windows ランナーで作っているので、
通常はそちらを使えば足ります。

インストーラーはユーザー単位のインストールなので
管理者権限は不要で、`%LOCALAPPDATA%\Programs\Listener\Listener.exe` に入り、
デスクトップとスタートメニューにショートカットが作られます。
設定の「Windowsサインイン時に自動起動」もこの形でのみ動作します。

`build.asar` を `false` にしてあるため、`src/` は素のファイルとして置かれ、
**インストーラー版でもアプリ内更新（数百KB）がそのまま使えます**。

### ソースから起動（開発時）

```powershell
npm start
```

`create-shortcut.ps1` を一度実行すると、`node_modules` の electron を指す
ショートカットがデスクトップとスタートメニューに作られます（コンソールは出ません）。
`start-listener.bat` でも起動できます。

### ポータブル版について

`npm run dist` で単体exeも作れますが、**起動のたびに一時フォルダへ展開して動く**ため、
アプリ内更新が次回起動に残りません。自動更新を使うならインストーラー版にしてください。

## 高速化

1. モデルを kotoba-whisper にする（最も効果大・日本語専用）
2. スレッド数を上げる（既定は論理コア数 − 2）
3. VADを有効にする（無音を除くため処理量が減る）

## 更新の配布（アプリ内アップデート）

配布するのは `src/` と `package.json` だけを固めた軽量zip（数百KB）です。
インストーラー丸ごと（80MB超）だと、大容量ダウンロードが切れる回線で
更新のたびに失敗しかねないためです。

### リリース手順

1. `package.json` の `version` を上げる
2. `CHANGELOG.md` に `## v0.8.1` の節を足して変更点を書く
3. コミットしてタグを push する

```bash
git tag -a v0.8.1 -m "リリース"
git push origin v0.8.1
```

`.github/workflows/release.yml` がテストを回し、zipを作り、Releaseを公開します。
`CHANGELOG.md` の該当節がそのままリリース本文になり、アプリの
[設定] → [アップデート] に表示されます。
タグと `package.json` のバージョンが食い違うとワークフローが止まります。

タグを push できない環境（プロキシが `refs/tags` を拒否する等）では、
Actions 画面の **Run workflow**、または `release/v0.8.1` という名前の
ブランチを push しても同じ結果になります（そのブランチは公開後に自動で消えます）。

各PCの Listener が起動時、または [設定] → [アップデート] → [更新を確認] で検出します。

手元でzipだけ作りたい場合（Releaseは手動で作る）:

```powershell
powershell -ExecutionPolicy Bypass -File .\make-release.ps1 -Version 0.8.1
```

適用前に現行の `src/` を `src.backup-*` として退避するので、
展開に失敗しても起動できなくなることはありません（1世代だけ残します）。

## テスト

```powershell
npm test
```

要約パイプライン（Markdown→ブロック→出典→担当・期限）、出典マッチング、
日付の正規化、アプリ内アップデート、IPCの整合、公開前チェック（個人情報の混入、
.ps1 の BOM+CRLF）を検証します。Node同梱のテストランナーだけを使うため、
追加の依存はありません。

エンジンを起動しない範囲の検証です。マイク・ホットキー・実際の
文字起こし精度・要約の文章品質は実機で確認してください。

## 実装について

オリジナル実装です。Notion・Typeless 等のコードやデザイン資産は含みません。
whisper.cpp（MIT）、llama.cpp（MIT）、Qwen2.5（Apache 2.0）をローカル実行しています。
追加のnpm依存はなく、electron と electron-builder のみで動作します。
